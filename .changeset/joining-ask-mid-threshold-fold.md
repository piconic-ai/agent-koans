Add koan 094: the caller's fold ask, instructions and all, arrives while the run's own declared threshold is already folding the conversation down. Koans 088/093 exercised joining only where the running fold was itself ask-initiated; nothing exercised the other origin, so an implementation whose join logic lived only in its ask path — one that queued a second fold for a threshold-caused fold, or leaked the ask's words into it — passed the whole suite. Joining and the reach-nothing rule do not depend on what began the fold: an ask that arrives mid-flight joins whichever fold is already running, ask-started or threshold-started alike, and its own instructions reach nothing. In the format, a compaction step itself may carry `joined_by:` for this origin, since there is no `compact:` turn to carry it instead; `CompactTurn`'s own `joined_by` stays how a joiner is written where the fold is already ask-initiated. The koan found a real defect in the bundled vanilla example — its join logic lived only in the ask path, so an ask mid-threshold-fold started a second fold — now fixed. The bundled Flue example cannot coordinate an ask with a threshold fold already in flight and is skipped with a reason.
